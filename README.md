# 指数新高新低复盘 - 工程目录说明

## 项目简介

A股指数新高新低复盘桌面工具（Python + Tkinter）。每日自动更新三指数（上证50 / 沪深300 / 中证2000）新高新低统计、板块 OBV 强势、大盘情绪（涨停/跌停/连板/炸板等）与基差数据，并支持大盘明细查看涨停板等个股，帮助短线复盘、可视化看盘。

- 仓库：https://github.com/kkwlkc/index-high-low-fupan
- 许可：MIT（见 `LICENSE`）

## 版本 v1.5（更新说明）

自 v1.4.11 起累积的里程碑版本，界面体验与计算核心同步升级（数据口径不变）：

**界面体验**
1. 记住使用习惯：窗口大小/位置、上次数据源、指数子选项卡关闭时保存到 `复盘_ui.json`，下次启动自动恢复；最小化时关闭不会把窗口坐标存成屏幕外（`-32000` 类）导致下次"看不见"。
2. 全局快捷键：`F5` 立即刷新、`Ctrl+E` 导出 xlsx、`Ctrl+1~4` 切换 大盘/指数/板块/两融。
3. 所有折线图支持悬停读数：竖向十字线自动吸附最近交易日 + 各序列标记点 + 数值面板（日期与具体数值），共 8 张图。
4. 指数页渲染后自动选中最新交易日，个股明细即时显示；明细区标题显示"日期：创新高 X 只 · 创新低 Y 只"。
5. 全部表格（含明细弹窗）隔行底色；表头点击排序（数值列自动识别、缺失值排末尾、▲/▼ 指示）；右键 / `Ctrl+C` 复制选中行可直接粘贴进 Excel。
6. 大盘表格行悬停高亮 + 手型光标，明确提示整行可点击查看当日明细。
7. 启动加载进度聚合显示"正在加载数据源（剩 N 项）…"，不再 6 路线程互相覆盖闪烁；修复切换数据源后【立即刷新】按钮卡在禁用态。
8. 每日自动更新完成提示带时间戳。

**计算核心**
9. `_aggregate_highlow` 改为向量化实现（去掉逐股 `DataFrame` 构造），中证2000 两千股场景该步骤提速约 6 倍（3.71s → 0.63s），启动与后台重算同步变快；`load_cons` / 板块列表等去掉 `iterrows`。
10. 代码审查修复：排序状态改用控件对象为键（避免弹窗控件 id 复用污染表头）、大盘数据未就绪时清空行命中数据（避免点击命中过期行）。

## 版本 v1.4.14（更新说明）

代码审查（open-code-review 流程 + 19 项确定性功能验证）后修复的 3 个边界场景 bug：

1. 修复排序状态字典以 `id(控件)` 为键的复用污染：大盘明细弹窗的 Treeview 频繁创建销毁，id 被新控件复用时，旧排序状态会把新表格的表头文字还原成错误内容。改为以控件对象本身为键；弹窗关闭时同步清理其排序状态（兼防内存缓慢累积）。
2. 修复"最小化时关闭 → 下次启动窗口跑到屏幕外"：Windows 下窗口最小化时 `geometry()` 返回 `-32000` 类坐标，原样保存并恢复会让窗口看不见也点不到；保存与恢复两侧均增加屏幕外坐标过滤。
3. 修复大盘数据加载失败后的残留命中：数据未就绪/加载失败时行命中数据 `_market_days` 仍保留上一次渲染的日期行，悬停高亮与点击会命中已不存在的行、弹出过期明细；占位提示与清空画布两条路径均已同步失效。

## 版本 v1.4.13（更新说明）

本版聚焦"看图读数"与计算核心提速（gui.py + server.py）：

1. 所有折线图支持**悬停读数**：鼠标移到图上任意位置，出现竖向十字线自动吸附最近交易日 + 各序列标记点 + 右上角数值面板（日期、各序列具体数值）。原来看图只能按网格目测估算，想确认某天数值要对照表格逐行找。适用于创新高/新低、基差、大盘最高板/连板、两融合计/日增减全部 8 张图；数据重绘后自动失效，不会读到过期数值。
2. 指数页渲染后**自动选中最新交易日**，个股明细立即显示（原实现明细区初始空白，用户不点日期行根本不知道那里能看个股）；明细区新增标题，显示"选中日期：创新高 X 只 · 创新低 Y 只"。
3. 每日自动更新完成提示带完成时间（HH:MM），常驻挂机时能确认最后一次更新发生在几点。
4. 计算核心提速：`_aggregate_highlow` 改为逐股直接抽数组 + rolling 向量化，去掉每只股票 `pd.DataFrame(rows)` 的逐行解析构造（中证2000 两千股每次 compute 都要重复，是启动重算的主要耗时之一，实测该步骤提速 3~5 倍）；`load_cons` / `load_block_list` / `load_block_constituents` 去掉 `iterrows`。口径不变（NaN 比较结果为 False，与原 notna 掩码一致）。

## 版本 v1.4.12（更新说明）

本版聚焦界面使用体验（gui.py），数据口径与计算核心（server.py）不变：

1. 记住使用习惯：窗口大小/位置、上次选择的数据源、指数子选项卡在关闭时保存到 `复盘_ui.json`（与日志同目录），下次启动自动恢复；配置损坏时静默回退默认值。
2. 全局快捷键：`F5` 立即刷新、`Ctrl+E` 导出 xlsx、`Ctrl+1/2/3/4` 切换 大盘/指数/板块/两融。
3. 启动加载进度聚合：原来 6 路预加载线程各自写状态栏、互相覆盖一闪一闪，现聚合显示"正在加载数据源（剩 N 项）：上证50　沪深300 …"，全部结束即不再覆盖视图状态。
4. 修复【立即刷新】按钮卡禁用：某数据源刷新中切换到另一数据源后，按钮停留在禁用态无法刷新；现按当前数据源的加载状态实时修正。
5. 所有表格支持表头点击排序：自动识别数值列（缺失值 `-` 排在末尾），再点一次反向，表头带 ▲/▼ 指示；数据重渲染后自动清除箭头。排序用 move 实现，不破坏选中状态与红/绿前景色。
6. 所有表格隔行浅灰底色（含大盘明细弹窗、指数个股明细、板块名称区），长表更好读。
7. 右键菜单 / `Ctrl+C` 复制选中行（制表符分隔，可直接粘贴进 Excel）。
8. 大盘表格行悬停高亮 + 手型光标：鼠标移到哪一行整行半透明高亮，明确提示"整行可点击查看当日明细"（原来没有任何视觉反馈，部分用户不知道表格能点）。
9. 代码整理：`_on_nav_change` 四段重复的 pack/forget 收敛为统一循环；大盘表头高/行高提取为模块常量（渲染、行点击、悬停共用）。

修复"两融数据未更新"（深市偶发取数失败 → 当日合计长期显示 `-`，且 6 小时内不再重试）：

1. 深市取数改为直连深交所「融资融券交易总量」报表接口（`/api/report/ShowReport/data`，`CATALOGID=1837_xxpl`，字段 `jrrzye` 单位已是亿元），并做 3 次退避重试。原实现走 `akshare.stock_margin_szse`：空响应直接抛 `ValueError` 且无重试，交易所偶发 SSL 断连（`UNEXPECTED_EOF_WHILE_READING`）会被当成"无数据"落库，该日合计就此永久为 `-`。
2. 京市（北交所）JSONP 取数同样加 3 次退避重试（`ReadTimeout` 在并发补齐时常见）。
3. 沪市区间接口区分"未发布"与"网络故障"：`Length mismatch` 视为当日无数据直接返回空，其余异常退避重试。
4. 重拉节流分级：最近 3 个交易日用 **3 分钟** TTL（数据当晚才陆续发布、接口偶发失败，6 小时节流会让当天整天显示 `-`），更早的缺市日仍用 6 小时 TTL，避免高频联网。
5. 手动【立即刷新】不再只重查最新交易日：最近 5 个交易日内的缺市日一律强制重拉（原来点了刷新也补不上更早的缺市日）。
6. 新增两融看门狗线程（5 分钟一轮）：最近交易日合计缺失时静默重拉，数据发布后自动上屏，无需手动刷新；数据无变化时不重绘、不覆盖状态栏。
7. 状态栏提示：最新交易日合计缺失时显式说明是"三市尚未发布"还是"某市数据缺失，后台自动重试中"，避免被误读成程序没更新。
8. 测试新增 `test_recent_missing_day_short_ttl`（共 6 项）：最近交易日缺市日走分钟级 TTL，较早缺市日仍走 6 小时节流。

## 版本 v1.4.7（更新说明）

修复"最新交易日两融数据显示为空 / 不刷新"：

1. 表格不再显示三市均未发布日期的空行：沪深京融资余额在交易日当晚才发布，程序在收盘后即把该交易日纳入统计，于是表里多出一行全 `-`，看上去像"今日没更新"。数据发布后该行会自动出现。

## 版本 v1.4.6（更新说明）

代码审查后的修复与整理（数据口径与稳定性，无新功能）：

1. 修复 watchdog 被两融拖成死循环：`margin_needs_refresh()` 原按"最新交易日 T 缺失"判定过期，而两融 T 日数据常滞后发布，导致每 120 秒拉起一次全量每日更新。改为按 **T-1** 判定（T 日缺失不驱动自动更新）。
2. 修复缺市数据仍算合计引发的万亿级虚假跳变：合计仅在沪深京三市都取到时才计算，缺任一市记 NULL（界面显示 `-`），且该日不参与"较前一日"基准。原实现用残缺数据求和，深市单日接口一失败就少约 1.17 万亿并永久错误。
3. 修复并发重入：联网补齐加全局非阻塞锁，多入口（预加载/切页/自动更新/手动刷新）同时调用时只有一路联网，其余直接读缓存返回，消除重复拉取与 SQLite 写冲突。
4. 缺市日重拉节流：6 小时内不重复联网；三市全空且已有历史值时保留原数据，不被网络故障覆盖成空。
5. 沪市改为只按实际缺失区间请求（原每次都从统计起点拉全区间）。
6. 北交所 JSONP 改用 `ast.literal_eval` 解析（原正则只补最后一个单引号日期字段，响应形态一变就静默失败）。
7. watchdog 让路条件补上 `margin_loading`；抽出金额格式化函数替代循环内的 lambda。
8. 新增离线用例 `tests/test_margin.py`（4 项）：三市齐全的合计与增减、缺市不出合计、缺市日不反复联网、T 日滞后不触发自动更新。

## 版本 v1.4.4（更新说明）

1. 修复板块统计永久加载失败：`get_block_obv_daily` 未声明 `global _BLOCK_REBUILD_TS`，缓存未命中（需全量重建）时读取该变量会抛 `UnboundLocalError`，板块页卡在"加载中，请稍候"永远出不来。缓存命中时该分支不会执行，所以只在跨日需要重建时才暴露。
2. 修复失败提示从不显示：`gui.py` 中 5 处后台回调写成 `lambda: ...(str(e))`，而 except 变量 `e` 在 except 块结束后会被 Python 解除绑定，回调执行时抛 `NameError`，导致"板块统计失败 / 刷新失败"等提示全部失效（改为默认参数传值）。
3. 修复成交总额后台回填被永久停用：嵌套函数 `_run` 未声明 `global _VOL_BG_ACTIVE`（外层函数的 global 不适用于嵌套函数），模块级标志复位不了，此后的回填请求全部被幂等判断挡掉，成交总额会长期显示"-"。
4. 增加模块级变量 global 遗漏的静态自检，避免同类问题再发。

## 版本 v1.4.2（更新说明）

1. 单实例保护：新增命名互斥体守卫，重复启动时**自动激活已打开的窗口**并退出，不再开出第二个实例。原实现允许多开，实测同时开 3 个实例时，其中一个实例的三个预加载线程会全部静默失败——界面永久空白、连启动日志都写不进去（用户只能看到白屏，误以为"数据出不来"）。

3. 加载中提示：大盘页在数据未就绪时绘制"正在加载数据…（首次打开或需联网补齐时约 1~3 分钟）"，不再是一片纯白。
4. 启动脚本修复：`启动复盘工具.bat` 曾因被保存为 UTF-8 无 BOM 而让 cmd 按 GBK 解释，中文路径变乱码导致"双击一闪而过"，现改为 GBK(ANSI) + CRLF，并加入程序缺失提示与 pause。

## 版本 v1.4.1（更新说明）

1. 基差改为"入库带证据、查询查证据"的**持续自愈机制**：当日基差行落库时同步记录参与合约数 n 与期望合约数 ref；自动更新的新鲜度判定升级为"覆盖关 + 质量关"双关——即便某个失真中间态意外入库（n < ref），下一轮也会被识别并联网重算覆盖，不再依赖"升级时一次性清理"这类只能救一次的措施。
2. 渲染层兜底：界面读缓存时若发现最新交易日行缺少"合约齐备"证据，宁可显示"-"也不展示失真数值，等后台补齐后再经回调自动刷新。
3. 版本号显性化：窗口标题与启动日志显示 `APP_VERSION`（v1.4.1），防止"源码已修复、仍在跑旧 exe"导致的部署错位。

## 版本 v1.4（更新说明）

1. 修复基差数值错误：新浪期货当日行情是**按合约分批延迟发布**的，旧版只要当日有 ≥1 个合约就做持仓量加权并落库，而远月合约贴水更深，缺失会让加权价虚高、基差虚低（实测 2026-09-09 上证50 显示 28.74、沪深300 显示 55.2，合约齐备后应为 46.23 / 71.94）。现改为以"近期正常合约数"为基准判定当日数据是否就绪，未就绪则剔除当日、不落库，由自动更新继续重试直到拉全。
2. 修复中证2000 基差长期不显示：期货合约日线是**进程级永久缓存**，若某合约在"当日数据未发布"时被拉取，之后所有强制刷新都只读这份旧快照，`force=True` 也拿不到新数据（实测中证2000/IM 连续 11 次重算都停在 T-1）。现按"缓存末条日期"判定是否过期，仅对仍在交易、但缺当日数据的合约重新联网。
3. 修复失真基差无法自愈：失真值一旦入库就会被判定为"已覆盖最新交易日"而停止重试，界面长期显示错误数值。现在未就绪时会主动删除当日行并保持缺失（显示"-"），同时升级后首次启动会清理一次当日基差缓存。
4. 基差补齐重试间隔由 20 分钟缩短为 10 分钟，判定"未就绪"时进一步缩短到 5 分钟，缩短当日基差的等待时间。
